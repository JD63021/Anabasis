# Anabasis v1.1c / pre4 Poisson-Decomp Handover
Date context: May 2026
Checkpoint purpose: reusable MPI-decomposed Poisson/elliptic library before scalar-transport port.

================================================================================
0. Status summary
================================================================================

This checkpoint creates a reusable decomposed Poisson/elliptic library:

  libpoisson_decomp/

and a validation app:

  apps/poisson_mms_decomp_gpu_mpi/

This replaces the earlier one-off PRE3C/PRE3D distributed Poisson proof apps with a more modular library that mirrors the original serial libpoisson structure, while adding OpenFOAM processor-patch MPI support.

Important: this is a correctness/modularity checkpoint, not final performance tuning. The HYPRE IJ matrix path in libpoisson_decomp currently uses host-side SetValues then migrates to device. Earlier prototype apps also proved device IJ insertion can work. Later optimization can move assembly/insertion fully back to device.

2. What libpoisson_decomp currently supports
================================================================================

Core capabilities:

  1. OpenFOAM decomposed case reading:
       caseRoot/processor<rank>/constant/polyMesh

  2. MPI rank ownership:
       dm.ilower, dm.iupper, dm.globalN

  3. Processor patch detection from OpenFOAM boundary files:
       type processor
       myProcNo
       neighbProcNo
       startFace
       nFaces

  4. Processor-face remote metadata exchange:
       remote global row for off-rank column
       remote cell center for processor face geometry

  5. Distributed scalar CSR pattern:
       local diagonal columns
       local internal owner-neighbour couplings
       off-rank processor-face columns

  6. Scalar halo exchange:
       exchange_proc_face_scalar_owner_values()

  7. Vector/gradient halo exchange:
       exchange_proc_face_vector_owner_values()

  8. Physical boundary BCs through original modular ScalarBCSet:
       Dirichlet
       Neumann

  9. MMS app can read pressure BC config from simple_gpu modular BC parser:
       pressure patch_0_0 fixed_value 0.0

  10. Variable gammaFace:
       solve_scalar_elliptic_decomp(dm, gammaFace, cellSource, bcSet, opts)

  11. Cell source term:
       cellSource[c] integrated as source * cellVolume

  12. Gradient options:
       gradScheme = lsq
       gradScheme = gauss

  13. Laplacian options:
       laplacianScheme = orth
       laplacianScheme = nonorth

  14. Non-orthogonal correction loop:
       nOuter = nNonOrthCorr + 1 for nonorth
       nOuter = 1 for orth

  15. Reference-cell option for pure Neumann cases:
       opts.useReferenceCell
       opts.referenceGlobalCell
       opts.referenceValue

  16. HYPRE distributed PCG + BoomerAMG solve through MPI_COMM_WORLD.

5. MMS equation and BC
================================================================================

Current MMS app solves:

  -laplacian(phi) = f

with:

  phi = sin(pi x) sin(pi y) sin(pi z)
  f   = 3 pi^2 phi

For the unit cube [0,1]^3, the exact boundary value is zero on all six faces.

Therefore the modular BC file is:

  /tmp/poisson_mms_cube.bc

with content:

  pressure patch_0_0 fixed_value 0.0

The app intentionally maps pressure patch BC specs to scalar Poisson BCs for testing compatibility with the original simple_gpu BC parser.

Wrong-BC sanity test:

  pressure patch_0_0 fixed_value 1.0

This gives L2 ~ 1, proving that the BC config is actually used.

Observed behavior:
  L2 and Linf decrease strongly with refinement.

    L2   = 1.637447790117e-02

  nonorth correction is essential on these ~50 degree non-orthogonal poly meshes.

10. Current caveats
================================================================================

1. HYPRE IJ insertion path:
   Current libpoisson_decomp uses host IJ SetValues and then migrates to device.
   This is acceptable for correctness/modularity now.
   Later performance work should move assembly/insertion back to device, following the old PRE3C2 device-IJ proof.

2. Multiple processor patches:
   Code supports a vector of processor patches and loops over them, but the validation so far is mainly 2 ranks / 1 proc patch per rank.
   Scalar transport and SIMPLE should keep this generalized structure.

3. GPU assembly:
   Current library assembly/gradient path is mostly host-side modular code.
   This is deliberate for closing correctness quickly.
   Later SIMPLE performance path should use GPU kernels once formulas are stable.

4. Boundary config:
   MMS app maps pressure BC config to scalar Poisson BCs.
   For scalar transport, use scalar-specific BCs or define transport BC parsing cleanly instead of abusing pressure names forever.

11. Next task: scalar transport decomp
================================================================================

Next layer should be:

  libscalar_decomp/

Goal:
  Use DecompMesh and processor-face halo infrastructure from libpoisson_decomp.
  Add convection/diffusion scalar transport with MMS.

Recommended structure:

  libscalar_decomp/include/scalar_decomp_library.h
  libscalar_decomp/src/scalar_decomp_library.cu

  apps/scalar_transport_mms_decomp_gpu_mpi/src/main.cu

Equation target:

  div(u phi) - div(Gamma grad(phi)) = S

Use MMS:
  phi_exact = sin(pi x) sin(pi y) sin(pi z)

Choose a simple divergence-free velocity for first test:
  u = (1, 0, 0) constant
or:
  u = (1, 1, 1) constant

Then source:
  S = u dot grad(phi) - Gamma laplacian(phi)

For phi = sin(pi x) sin(pi y) sin(pi z):

  grad(phi) =
    [pi cos(pi x) sin(pi y) sin(pi z),
     pi sin(pi x) cos(pi y) sin(pi z),
     pi sin(pi x) sin(pi y) cos(pi z)]

  laplacian(phi) = -3 pi^2 phi

So:

  S = u dot grad(phi) + 3 Gamma pi^2 phi

First scalar transport options:
  Gamma constant
  upwind convection
  central diffusion
  LSQ nonorth diffusion correction reused from libpoisson_decomp
  fixed_value Dirichlet on patch_0_0 for MMS exact boundary

Processor-face scalar transport requirements:
  - processor-face remote phi halo
  - processor-face remote grad halo
  - processor-face remote cell center
  - processor-face flux F_f = u_f dot S_f
  - upwind:
      if F_f >= 0: use local owner phi
      else: use remote halo phi
  - diffusion:
      same off-rank column treatment as libpoisson_decomp
  - nonorth correction:
      same gradient halo treatment as libpoisson_decomp

Use libpoisson_decomp pieces directly where possible:
  DecompMesh
  build_decomp_scalar_pattern
  exchange_proc_face_scalar_owner_values
  exchange_proc_face_vector_owner_values
